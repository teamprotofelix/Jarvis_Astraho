# PR7 선택과 아카식

9개 일회성 장면/각 3개 선택을 제공한다. 신호 스캔 완료, 협곡 접근, 정상 표본 회수 후 임무 완료, 격납고/연구실/온실 가동, E와 마리의 실제 같은 방 serve/rest, 실제 초대 미확인 신호 검토, 서로 다른 결정 3건에 연결한다. 화면 render나 무작위 timer는 사건을 생성하지 않는다. Campaign은 순수 변경 비교와 crew 전이 관측만 story engine에 전달한다.

pending FIFO의 eventId+choiceId+eventSequence를 검증해 한 번만 결정한다. 자원·연구 비용·초대 여부·원정 잠금을 바꾸지 않는다. 선택은 플래그/즉시 결과/아카식 기록/해당 발화자의 다음 대사를 바꾸며, 다음 실제 미션·거래·승무원 전이에서 해당 선택의 후속 기록을 남긴다. 관찰·보류·비개입은 불이익이나 영구 봉쇄가 아니다. gravity_orchard는 모든 선택 후에도 진입 불가다.

자비스는 근거와 미확인을 구분하고, 서아는 인적 판단, 스쿨드는 기술 작업, 미르와 세계수는 독립 존재로 다룬다. 마리의 비공개 내면은 생성·전파하지 않는다. 대사는 공개용 새 창작이며 실제 과거 대화나 실시간 AI 집필이 아니다. 여러 인물 관련 장면도 실제 발화자의 대사만 해당 인물에게 연결한다.

기존 고정 JARVIS LOG 12편은 그대로이며 별도 ‘선택·아카식 분기’ 화면/필터/모달에서 새 기록을 읽는다. 사건은 자동 팝업으로 진행을 막지 않고 알림 버튼에서 열며 Escape로 나중에 결정할 수 있다. 모달은 기존 inert/포커스 트랩/복원을 사용하고 선택 완료 시 이야기 제목으로 포커스를 옮긴다. v4 이전 저장은 이야기 미진행으로 시작하며, 이미 성취한 실제 시설·신호·귀환을 사용자가 ‘기록 검토’로 다시 열 수 있다. 과거에 선택했다고 추론하지 않는다.

## 저장과 상한

schema5의 story는 sequence/revision/seenTriggerIds/pending/resolved/flags/journal이다. 장면별 한 번: pending+resolved≤9, flag≤9, journal≤18(결정+후속), revision≤27. 결정을 삭제해 잘라내지 않고 고정 범위로 보존한다. trigger/source/choice/sequence/time/flag/기록 참조를 검증한다. journal summary는 240자 이하 텍스트이고 HTML로 실행하지 않고 escape한다. v1→v5는 복사본에서 단계별 기존 검증과 기본값을 적용한다. 미래 버전·손상 파일은 원본을 보존한다. current/before-import 및 multi-tab 저장 충돌 보호는 유지한다.

## 아트

첨부 스토리 WebP 27개: scene 9/thumbnail 9/symbol 9. 기존 프로젝트 원본 5장 기반의 새 합성·색보정 이미지와 독립 심볼이며 새 텍스트-이미지 생성 결과라고 주장하지 않는다. 전체 4,298,882 bytes. 고화질 한 장은 최대 433,504 bytes로 첨부 원본 그대로 검증하며, 이 신규 묶음은 512,000 byte 상한을 별도 적용한다. 기존 51+19+25 아트의 기존 크기/해시 검사는 유지한다.

모달을 열 때 해당 scene만 요청한다. 모바일/low quality는 960×540 thumbnail을 우선한다. 오류는 thumbnail→기존 함교 scene→색 레이어로 폴백하고 텍스트/선택은 계속 가능하다. 설치 필수 캐시에 9개 고화질을 넣지 않는다.
